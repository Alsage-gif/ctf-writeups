# Ignite — Fuel CMS и PwnKit

## Разведка

Начал с анализа веб-приложения Fuel CMS.

![Главная страница Ignite](../images/Pasted%20image%2020260329005643.png)

![Версия и структура приложения](../images/Pasted%20image%2020260329005725.png)

На сервере использовалась Fuel CMS `1.4.1`, для которой известна уязвимость CVE-2018-16763.

## Получение web-shell

Приложение жёстко фильтровало часть запросов, поэтому готовый эксплойт пришлось адаптировать.

![Проверка уязвимого параметра](../images/Pasted%20image%2020260329011122.png)

Эксплуатация CVE-2018-16763 дала выполнение команд от имени `www-data`.

![Рабочий вариант эксплойта](../images/Pasted%20image%2020260329012843.png)

Затем получил reverse shell и начал локальную разведку.

![Полученный reverse shell](../images/Pasted%20image%2020260329014848.png)

## PwnKit

Проверка `sudo` сначала завершилась ошибкой:

```text
no tty present and no askpass program specified
```

Причина — shell не имел интерактивного TTY.

![Ошибка sudo в нестабильной оболочке](../images/Pasted%20image%2020260329015038.png)

После проверки SUID-файлов обнаружил `/usr/bin/pkexec`. На старой Ubuntu 16.04 он был уязвим к CVE-2021-4034 (PwnKit). Так как на сервере не было `curl` и `wget`, код эксплойта пришлось собрать непосредственно на машине через `gcc`.

Перед использованием `sudo` стабилизировал терминал:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

![Стабилизация TTY](../images/Pasted%20image%2020260329022517.png)

После запуска PwnKit получил root-shell. Эксплойт изменил `PATH`, поэтому стандартные команды сначала не находились. Восстановил окружение:

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

После этого прочитал root-флаг.

## Итог

1. Определил Fuel CMS 1.4.1.
2. Эксплуатировал CVE-2018-16763 и получил web-shell.
3. Стабилизировал TTY.
4. Собрал и запустил PwnKit на старой Ubuntu.
5. Восстановил `PATH` после эксплойта и получил root.
