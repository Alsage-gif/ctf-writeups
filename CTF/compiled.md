# Compiled — анализ бинарника через `strings` и GDB

## Первичная проверка

В задаче был исполняемый файл без исходного кода. Сначала я извлёк из него печатные строки:

```bash
strings ./compiled
```

![Результат запуска strings](../images/Pasted%20image%2020260329030835.png)

Среди строк встретился шаблон `DoYouEven%sCTF`. Это подсказало, что программа ожидает ввод с фиксированным префиксом и суффиксом, а проверять будет значение между ними.

## Анализ в GDB

Чтобы понять реальную логику проверки, я открыл бинарник в GDB и поставил остановку перед вызовом `strcmp`.

Полезная последовательность выглядела так:

```gdb
disas main
break strcmp
run
```

В Linux первые аргументы функции передаются через регистры `$rdi` и `$rsi`. Перед `strcmp` в них находились две сравниваемые строки: очищенный пользовательский ввод и эталонное значение.

Вместо перебора я ввёл:

```text
DoYouEven_initCTF
```

После обработки шаблона программа сравнила внутреннее значение `_init` с ожидаемой строкой, и проверка завершилась успехом.

## Что показала задача

- `strings` быстро раскрывает подсказки и текстовые константы в бинарниках.
- `disas main` помогает найти функции ввода и сравнения.
- Точка останова на `strcmp` позволяет увидеть фактические аргументы проверки.
- GDB показывает данные в регистрах и памяти, даже если исходный код недоступен.

Для более глубокого анализа такого бинарника я бы использовал Ghidra или GDB с расширением pwndbg: это упростило бы просмотр функций, стека и аргументов.
