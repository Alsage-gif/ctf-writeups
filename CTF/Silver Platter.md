## Повышение привилегий через Docker

Пользователь входил в группу `docker`. Это практически эквивалентно root-доступу: Docker daemon работает с привилегиями root и позволяет примонтировать корневую файловую систему хоста в контейнер.

```bash
docker run -v /:/mnt --rm -it alpine chroot /mnt sh
```

После монтирования `/` в `/mnt` каталог `/mnt/root` соответствовал реальному `/root` на хосте. Для неинтерактивного чтения флага можно использовать:

```bash
docker run -v /:/mnt --rm alpine cat /mnt/root/root.txt
```

В исходной заметке зафиксирован результат с root-доступом.

## Выводы

- Не стоит зацикливаться на одной точке входа: после получения админского доступа я сначала искал RCE, хотя полезнее было проверить сообщения, логи и резервные файлы.
- Файлы `backup`, ZIP-архивы и изображения нужно проверять вместе с метаданными и скрытым содержимым.
- Команда `id` после получения нового пользователя обязательна: членство в группе `docker` сразу меняет модель угроз.
- Silverpeas нужно обновить, закрыть обход аутентификации и ограничить доступ к административным функциям.
- Пользователей нельзя добавлять в группу `docker` без отдельного обоснования; для контейнеров стоит применять rootless-режим и минимальные права.
