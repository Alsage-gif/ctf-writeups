# Room 404 — утечка Git-репозитория

## Разведка

Начал с полного сканирования хоста:

```bash
nmap -sC -sV -p- 10.81.155.222
```

![Результат Nmap-сканирования Room 404](../images/Pasted%20image%2020260810192738.png)

На хосте обнаружились открытые порты `22/tcp` и `8080/tcp`. Веб-приложение на `8080` стало основной точкой входа.

## Обнаружение `.git`

При перечислении директорий я обнаружил открытую директорию `.git`. Это означает, что веб-сервер отдаёт внутренние файлы Git-репозитория.

Такая ошибка приводит к утечке:

- исходного кода;
- удалённых файлов;
- истории коммитов;
- секретов, которые разработчик когда-то добавил в проект, а затем удалил.

## Разбор SHA-1 и восстановление репозитория

В процессе анализа мне встретилась строка длиной 40 символов:

```text
0f13550b4cb13e9f30c61d5b342c532d21e45bda
```

Сначала я принял её за хэш пароля и попробовал подобрать значение через `hashcat`. Подход не сработал. Контекст `.git` подсказал, что это не пароль, а идентификатор Git-коммита: Git также использует 40-символьные SHA-1-хэши.

Чтобы скачать содержимое репозитория, я использовал `git-dumper`, после чего посмотрел историю:

```bash
git show 0f13550b4cb13e9f30c61d5b342c532d21e45bda
```

## Поиск флага в истории

Команда показала изменения, в которых были добавлены `README.md`, `app.js` и `index.html`. В старом `README.md` разработчик оставил тестовый флаг с пометкой, что его нужно удалить перед запуском.

![Содержимое коммита с тестовым флагом](../images/Pasted%20image%2020260810194504.png)

Флаг сохранился в истории Git, хотя в актуальной версии сайта его уже не было.

## Итог

Открытая директория `.git` позволяет получить не только текущие файлы, но и предыдущие версии проекта. Удаление секрета из последнего коммита не защищает его, если он остался в истории.

Для защиты нужно закрывать доступ к `.git` на веб-сервере и проверять историю репозитория перед публикацией.
