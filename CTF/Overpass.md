# Overpass — DOM XSS и получение SSH-ключа

## Разведка

Начал с анализа веб-приложения и его JavaScript-кода.

![Первичный этап разведки Overpass](../images/Pasted%20image%2020260413182230.png)

![Фрагмент JavaScript-кода приложения](../images/Pasted%20image%2020260413185026.png)

В коде я заметил, что значение cookie `SessionToken` попадает в DOM без безопасного экранирования. Проверил гипотезу через DOM XSS:

```javascript
document.cookie = "SessionToken=<img src=x onerror=alert(1)>"
```

После перехода на `/admin` payload выполнился в контексте страницы администратора. В результате я получил доступ к SSH-ключу, который отображался только в административной части приложения.

![SSH-ключ, доступный после срабатывания XSS](../images/Pasted%20image%2020260413184900.png)

## Восстановление passphrase SSH-ключа

Ключ оказался защищён passphrase. Подготовил его для John the Ripper:

```bash
ssh2john id_rsa > hash.txt
john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt
```

![Подготовка ключа к подбору passphrase](../images/Pasted%20image%2020260413185758.png)

![Процесс подбора passphrase](../images/Pasted%20image%2020260413185804.png)

![Найденное значение passphrase](../images/Pasted%20image%2020260413190048.png)

После восстановления passphrase использовал ключ для подключения к серверу.

## Постэксплуатация

В системе запустил `linpeas` и обнаружил запрос, который выполнялся к доменному имени. Я связал это с возможностью подменить разрешение имени через `/etc/hosts`.

![Запрос, обнаруженный в выводе linpeas](../images/Pasted%20image%2020260413192549.png)

Добавил нужное сопоставление в `/etc/hosts`, запустил listener и дождался обратного соединения.

![Получение обратного соединения после подмены hosts](../images/Pasted%20image%2020260413192647.png)

## Итог

1. Проанализировал JavaScript и обнаружил DOM XSS.
2. Выполнил payload через значение `SessionToken`.
3. Получил SSH-ключ из административной страницы.
4. Восстановил его passphrase через John the Ripper.
5. Использовал вывод `linpeas` и подмену `/etc/hosts` для следующего этапа доступа.

Главный технический вывод: даже простая DOM XSS становится серьёзной проблемой, если административная страница отображает конфиденциальные данные в том же DOM-контексте.
