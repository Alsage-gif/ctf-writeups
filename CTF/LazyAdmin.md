## Повышение привилегий

При проверке `sudo -l` выяснилось, что пользователь мог запускать Perl и backup-скрипт с правами root. Backup, в свою очередь, вызывал отдельный `shell.sh`.

![Доступные через sudo команды](../images/Pasted%20image%2020260318161016.png)

![Связь backup-скрипта с вызываемым файлом](../images/Pasted%20image%2020260318161642.png)

Я проверил права на запись и обнаружил, что вызываемый скрипт можно изменить. В него был добавлен reverse shell, после чего запуск разрешённого backup-скрипта привёл к выполнению кода от имени root.

![Проверка прав на запись в вызываемый скрипт](../images/Pasted%20image%2020260318161712.png)

![Получение root shell через изменённый backup-скрипт](../images/Pasted%20image%2020260318161908.png)

## Вывод

Цепочка атаки: резервный файл → хеш пароля → панель SweetRice → загрузка PHP → пользовательский shell → `sudo` для backup → запись в вызываемый root-скрипт.

Основные исправления: удалить резервные файлы из web-root, не хранить пароли в слабых хешах, запретить загрузку исполняемого PHP, ограничить `sudo` конкретными безопасными действиями и запретить запись в скрипты, запускаемые от root.
