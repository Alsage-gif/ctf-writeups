Я находился внутри Docker-контейнера. В контейнере не было Python, поэтому стандартная команда стабилизации TTY не подошла. Вместо неё использовал `script`:


## Переход на хост

Проверил доступные файлы и обнаружил SQLite-базу. Для её анализа использовал небольшой PHP-скрипт, потому что штатные инструменты не помогли.

![Обнаруженная SQLite-база](../images/Pasted%20image%2020260328204605.png)

![Результат анализа базы](../images/Pasted%20image%2020260328204922.png)

Попытка подобрать найденный хэш результата не дала. После этого проверил домашние каталоги и обнаружил SSH-ключ пользователя `think`.

![Попытка анализа хэша](../images/Pasted%20image%2020260328210007.png)

![Найденный SSH-ключ](../images/Pasted%20image%2020260328210017.png)

Скопировал ключ на Kali, выставил права `600` и подключился к хосту:

```bash
chmod 600 id_rsa
ssh -i id_rsa think@10.114.169.225
```

## Обход AppArmor и повышение привилегий

На хосте проверил SUID-файлы, capabilities и запущенные сервисы. Наиболее интересными оказались:

- SUID-бинарник `/usr/sbin/run_container`;
- скрипт `/opt/run_container.sh`, который вызывается этим бинарником;
- профиль AppArmor, ограничивающий запись и выполнение по исходным путям.

Проверка показала необычную ситуацию: права Linux позволяли работать с файлом, но запись блокировалась AppArmor. Чтобы выйти из-под ограничений профиля, скопировал Bash в `/dev/shm`:

```bash
cp /bin/bash /dev/shm/shell
/dev/shm/shell -p
```

В этой оболочке изменил вызываемый SUID-бинарником скрипт:

```bash
echo "chmod +s /bin/bash" > /opt/run_container.sh
/usr/sbin/run_container
```

После запуска `run_container` скрипт выполнился с правами root и установил SUID-бит на `/bin/bash`. Привилегированную оболочку получил командой:

```bash
/bin/bash -p
```

## Итоговая цепочка

1. Определил SPIP и использовал CVE-2023-27372 для получения RCE.
2. Получил shell `www-data` внутри Docker-контейнера.
3. Нашёл SSH-ключ пользователя `think` и перешёл на хост.
4. Обнаружил связку AppArmor + SUID-бинарник `run_container`.
5. Скопировал Bash в `/dev/shm`, изменил вызываемый скрипт и получил root.

Основная ошибка конфигурации — привилегированный SUID-бинарник доверял внешнему скрипту, который можно было изменить после обхода ограничения AppArmor.
