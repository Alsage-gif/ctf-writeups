# Oh My Web — Apache path traversal, RCE и OMIGOD

## Path Traversal в Apache

Веб-сервер использовал Apache с уязвимостью CVE-2021-41773. Она позволяла обходить корень веб-приложения через URL-кодирование последовательности `../`.

Вместо обычного пути использовал:

```text
.%2e/%2e%2e/
```

Такой вариант после декодирования превращается в переход на родительские директории и позволяет читать файлы за пределами web-root.

## RCE через CGI

На сервере была доступна директория `/cgi-bin/`. В отличие от обычной директории, файлы в ней могут исполняться как CGI-программы.

Проверил запрос к `/bin/sh` через traversal:

```text
/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh?whoami
```

Веб-сервер выполнил команду `whoami` и вернул пользователя `daemon`.

## Получение интерактивного shell

Обычный reverse-shell payload проходил через фильтры нестабильно. Поэтому закодировал команду в Base64 и декодировал её на сервере.

![Передача команды в Base64](../images/Pasted%20image%2020260702123232.png)

После получения shell стабилизировал TTY:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
stty raw -echo; fg
export TERM=xterm-256color
```

## Переход из контейнера на хост

Проверка `linpeas` показала опасные capabilities у Python:

```bash
getcap -r / 2>/dev/null
```

![Найденные capabilities](../images/Pasted%20image%2020260702130737.png)

Однако наиболее надёжным вектором оказался не прямой escape через capabilities, а доступный из контейнера сервис хоста. По gateway контейнера определил адрес хоста и просканировал его порты. На `5986/tcp` обнаружил OMI.

## OMIGOD (CVE-2021-38647)

OMI — Open Management Infrastructure, сервис управления Linux-системами. Уязвимость CVE-2021-38647 позволяла вызвать `ExecuteCommand` через SOAP/XML без аутентификации.

Общий порядок эксплуатации:

1. Определить gateway контейнера через `ip route`.
2. Проверить порт `5986`.
3. Отправить SOAP-запрос на `/wsman`.
4. Вызвать `ExecuteCommand` класса `SCX_OperatingSystem`.
5. Передать reverse-shell команду.

![SOAP-запрос к OMI](../images/Pasted%20image%2020260702133645.png)

![Получение shell на хосте](../images/Pasted%20image%2020260703125255.png)

Команда выполнялась на хосте от имени root, поэтому reverse shell дал полный доступ к системе за пределами контейнера.

## Итоговая цепочка

1. Эксплуатировал Apache CVE-2021-41773.
2. Получил RCE через CGI и `/bin/sh`.
3. Стабилизировал shell внутри контейнера.
4. Определил адрес хоста из контейнерной сети.
5. Обнаружил OMI на порту `5986`.
6. Использовал OMIGOD для выполнения команды root на хосте.

Главный вывод: Docker-контейнер не изолирует приложение от уязвимых сервисов хоста, если сетевой интерфейс хоста доступен из контейнера.
