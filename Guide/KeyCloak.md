# 🔑 Keycloak для начинающих

Ниже собрал базовую модель Keycloak, основные термины и минимальный пример локальной настройки.

## 📖 Что такое Keycloak?

**Keycloak** — это система управления идентификацией и доступом (IAM), которая позволяет:
- Реализовать **единый вход (SSO - Single Sign-On)** для нескольких приложений
- Управлять пользователями, ролями и правами доступа
- Защитить приложения централизованной авторизацией

**Простыми словами:** Keycloak — это как "единый пропуск" в офис. Вместо того чтобы получать отдельный ключ от каждой двери (приложения), ты получаешь один пропуск, который открывает все нужные двери.

## 🎯 Зачем он нужен?

### Проблема без Keycloak:
Представь, что у компании есть:
- Веб-сайт
- Мобильное приложение
- CRM-система
- Почтовый сервис

**Без Keycloak:** 
- Пользователь регистрируется в каждой системе отдельно
- Нужно помнить 4 разных логина и пароля
- Если сменить пароль — то в 4 местах
- Разработчикам нужно писать систему безопасности для каждого приложения

**С Keycloak:**
- Одна регистрация и один вход для всех систем
- Разработчики просто подключаются к Keycloak
- Централизованное управление пользователями

## 🔧 Основные возможности

1. **Single Sign-On (SSO)** — вход один раз, доступ к нескольким приложениям
2. **Social Login** — вход через Google, Facebook, GitHub и другие провайдеры
3. **Поддержка стандартов:**
   - OpenID Connect (OIDC)
   - OAuth 2.0
   - SAML 2.0
4. **Двухфакторная аутентификация (2FA)**
5. **Управление ролями и правами доступа**

##  Примеры использования

### Пример 1: Веб-приложение с авторизацией

**Сценарий:** У тебя есть интернет-магазин и блог на разных поддоменах

```
Пользователь → shop.example.com → Keycloak (вход) → 
               blog.example.com (уже авторизован!)
```

Без повторного ввода пароля!

### Пример 2: Корпоративная система

Компания использует:
- CRM (для менеджеров)
- ERP (для бухгалтерии)
- HR-портал (для кадров)

**Решение:**
- Сотрудник входит один раз через Keycloak
- Keycloak проверяет его роль (менеджер/бухгалтер/кадровик)
- Открывает доступ только к нужным системам

### Пример 3: Мобильное приложение + API

```javascript
// Пример кода: вход через Keycloak
const keycloak = new Keycloak({
    url: 'http://localhost:8080',
    realm: 'my-realm',
    clientId: 'my-app'
});

keycloak.init({ onLoad: 'login-required' }).then(authenticated => {
    if (authenticated) {
        // Пользователь вошел, можно делать запросы к API
        const token = keycloak.token;
        api.get('/profile', { headers: { Authorization: `Bearer ${token}` }});
    }
});
```

## 🏗️ Основные понятия (термины)

| Термин | Что это | Пример |
|--------|---------|--------|
| **Realm** | Изолированное пространство с пользователями и настройками | `master`, `production`, `development` |
| **Client** | Приложение, которое подключается к Keycloak | `web-app`, `mobile-app`, `api-service` |
| **User** | Пользователь | `ivan@mail.ru`, `admin` |
| **Role** | Роль (набор прав) | `admin`, `user`, `manager` |
| **Group** | Группа пользователей | `developers`, `sales` |
| **Token** | Цифровой пропуск (JWT) | Access Token, ID Token, Refresh Token |

## 🚀 Простой пример настройки

### Шаг 1: Установить Keycloak

```bash
# Запуск через Docker
docker run -p 8080:8080 \
  -e KEYCLOAK_ADMIN=admin \
  -e KEYCLOAK_ADMIN_PASSWORD=admin \
  quay.io/keycloak/keycloak:latest \
  start-dev
```

### Шаг 2: Создать Realm
1. Зайти в админку: http://localhost:8080
2. Войти как `admin`
3. Создать новый realm (например, `my-app`)

### Шаг 3: Создать Client
1. В разделе **Clients** → **Create**
2. Выбрать тип: `OpenID Connect`
3. Указать `Client ID`: `my-web-app`
4. Настроить redirect URI: `http://localhost:3000/*`

### Шаг 4: Создать пользователя
1. В разделе **Users** → **Add user**
2. Имя: `testuser`
3. Задать пароль во вкладке **Credentials**

### Шаг 5: Подключить приложение

```javascript
// React/Vue/Angular приложение
import Keycloak from 'keycloak-js';

const keycloak = new Keycloak({
  url: 'http://localhost:8080',
  realm: 'my-app',
  clientId: 'my-web-app'
});

// Инициализация
keycloak.init({ onLoad: 'login-required' })
  .then(authenticated => {
    console.log('Пользователь авторизован:', authenticated);
    console.log('Токен:', keycloak.token);
  });
```

## 📊 Визуальная схема работы

```
┌─────────────┐
│  Пользователь│
└──────┬──────┘
       │ 1. Хочет войти в приложение
       ▼
┌─────────────┐
│  Приложение │
└──────┬──────┘
       │ 2. Перенаправляет на Keycloak
       ▼
┌─────────────┐
│   Keycloak  │ ← 3. Проверяет логин/пароль
└──────┬──────┘
       │ 4. Возвращает токен (JWT)
       ▼
┌─────────────┐
│  Приложение │ ← 5. Доступ разрешен!
└─────────────┘
```

# 🛡️ Уязвимости в Keycloak: Что нужно знать

Keycloak — это мощный инструмент, и сам по себе он довольно безопасен. Однако **большинство проблем возникает из-за неправильной настройки** или использования устаревших версий.

Как студенту и будущему специалисту, тебе важно понимать, где могут быть «дыры», чтобы их закрыть. Вот основные категории уязвимостей:

---

## 1️⃣ Конфигурационные ошибки (Самые частые)

Это не баги в коде Keycloak, а ошибки администратора.

| Уязвимость | Суть проблемы | Чем опасно | Как исправить |
|------------|---------------|------------|---------------|
| **Отсутствие HTTPS** | Keycloak работает по HTTP | Токены и пароли перехватываются в сети (MitM-атака) | Включить **HTTPS Required** в настройках Realm |
| **Слабая политика паролей** | Разрешены пароли типа `12345` | Легко подобрать методом перебора | Настроить **Password Policy** (длина, спецсимволы, история) |
| **Открытые редиректы** | В настройках Client указан `*` или широкий шаблон в `Valid Redirect URIs` | Злоумышленник может перенаправить пользователя на фишинговый сайт после входа | Указывать только конкретные домены (например, `https://myapp.ru/*`) |
| **Публичные клиенты без секрета** | Клиент типа `Public` используется для конфиденциальных данных | Токены могут быть украдены через XSS | Для серверных приложений использовать тип `Confidential` с `Client Secret` |

---

## 2️⃣ Уязвимости токенов и протоколов

Keycloak использует JWT (JSON Web Tokens). Если их неправильно обрабатывать, возникают риски.

### 🔹 Подделка токена (JWT `alg: none`)
*   **Суть:** В старых версиях или при неправильной настройке сервер мог принимать токены с алгоритмом подписи `none`.
*   **Атака:** Злоумышленник меняет содержимое токена (например, повышает себе роль до `admin`), убирает подпись и отправляет серверу.
*   **Защита:** Keycloak сейчас строго проверяет алгоритмы. Убедись, что используется **RS256** (асимметричная подпись), а не `HS256` (симметричная), если возможно.

### 🔹 Утечка токенов в логах
*   **Суть:** Токены доступа (Access Token) могут попадать в логи приложения или Keycloak.
*   **Атака:** Если хакер получит лог, он сможет использовать токен до истечения его срока жизни.
*   **Защита:** Настроить логирование так, чтобы тела токенов не писались в plain text. Использовать короткое время жизни токенов (например, 5-15 минут).

### 🔹 Долгая жизнь Refresh Token
*   **Суть:** Refresh Token используется для получения нового Access Token без ввода пароля.
*   **Атака:** Если он украден и живет полгода, хакер имеет доступ полгода.
*   **Защита:** Включить **Refresh Token Rotation** (при использовании токен старый уничтожается) и сократить срок жизни.

---

## 3️⃣ Атаки на аутентификацию

### 🔹 Brute-force (Перебор паролей)
*   **Суть:** Бот пытается подобрать пароль тысячами вариантов.
*   **Защита:** В Keycloak есть встроенная защита:
    *   **Brute Force Detection** (в настройках Realm).
    *   После N неудачных попыток — временная блокировка пользователя.
    *   Обязательно включи эту функцию!

### 🔹 Enumeration (Перебор пользователей)
*   **Суть:** Система по-разному реагирует на ошибки:
    *   `Пользователь не найден` (значит, такого нет)
    *   `Неверный пароль` (значит, пользователь есть)
*   **Атака:** Хакер собирает базу существующих логинов.
*   **Защита:** Настроить единое сообщение об ошибке: `Неверный логин или пароль`.

---

## 4️⃣ Уязвимости интеграции (Identity Brokering)

Keycloak позволяет входить через соцсети (Google, GitHub) или другие IDP.

### 🔹 SSRF (Server-Side Request Forgery)
*   **Суть:** При настройке брокера идентичности Keycloak может делать запросы к внешним URL.
*   **Атака:** Злоумышленник может заставить Keycloak сканировать внутреннюю сеть компании.
*   **Пример CVE:** **CVE-2023-5762** (критическая уязвимость в версиях до 23.0.4).
*   **Защита:** **Обновлять Keycloak!** и ограничивать доступ сервера к внутренней сети.

### 🔹 Account Linking (Привязка аккаунтов)
*   **Суть:** Автоматическая привязка внешнего аккаунта (например, Google) к локальному по совпадению email.
*   **Атака:** Если хакер зарегистрировался в Google с тем же email, что и админ в Keycloak, он может получить доступ.
*   **Защита:** Отключить автоматическую привязку (`Auto Link`) для критичных систем. Требовать подтверждения.

---

## 5️⃣ Известные CVE (Баги в коде)

В Keycloak периодически находят уязвимости. Вот несколько недавних примеров, чтобы ты понимал важность обновлений:

| CVE | Год | Описание |
|-----|-----|----------|
| **CVE-2024-1578** | 2024 | Позволяла связать аккаунт злоумышленника с существующим пользователем через брокер идентичности. |
| **CVE-2023-5762** | 2023 | SSRF через настройку брокеров идентичности (можно сканировать внутреннюю сеть). |
| **CVE-2022-3613** | 2022 | Уязвимость в проверке подписи токенов (можно было подделать токен). |

> ⚠️ **Вывод:** Всегда используй последнюю стабильную версию (LTS).

## 🛠️ Чек-лист безопасности для тебя

Если ты настраиваешь Keycloak (для учебы или работы), проверь эти пункты:

1.  [ ] **Версия:** Установлена последняя стабильная версия.
2.  [ ] **HTTPS:** Принудительное использование HTTPS включено.
3.  [ ] **Пароли:** Политика сложности паролей настроена (мин. 8 символов, цифры, буквы).
4.  [ ] **Блокировка:** Защита от перебора (Brute Force Detection) включена.
5.  [ ] **Клиенты:** Проверены `Valid Redirect URIs` (нет звездочек `*`).
6.  [ ] **Токены:** Время жизни Access Token ≤ 15 мин, включена ротация Refresh Token.
7.  [ ] **Админка:** Доступ к консоли администратора закрыт файрволом (не виден из интернета).
8.  [ ] **Логи:** В логах не сохраняются токены и пароли.
